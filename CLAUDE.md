# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Visão Geral

**BlessImport** é um importador de dados (aplicação desktop VCL, Delphi 11 Alexandria, Win32) para os ERPs da Bless Sistemas (SIDI, FINANCE, INJET). Serve para migrar os dados do sistema anterior de um cliente novo para esses ERPs por meio de **perfis de importação configuráveis e reutilizáveis** (planilha `.xls` → uma tabela do ERP por vez: mapeamento de campos, origem dos valores, transformações, referências, estratégia de gravação), sem escrever uma rotina por cliente.

A especificação está em `docs/projeto.md`. O plano de trabalho aprovado divide o projeto em tarefas pequenas (T01…T11); cada tarefa é implementada, compilada, testada pelo usuário e aprovada antes da próxima. Não adiantar tarefas.

## Build

Delphi 11 = `Studio\22.0`. Abrir `BlessImport.dproj` na IDE ou, num prompt `cmd`:
```
call "C:\Program Files (x86)\Embarcadero\Studio\22.0\bin\rsvars.bat"
msbuild BlessImport.dproj /t:Build /p:Config=Debug /p:Platform=Win32
```
O exe sai em **`bin\BlessImport.exe`** (junto de `bin\Config.ini` e `bin\data\`); DCUs em `.\$(Platform)\$(Config)`. Pelo bash do Claude Code, `cmd //c 'call ...'` não funciona — gravar um `.bat` com as duas linhas e executá-lo pela ferramenta PowerShell.

**DUnit clássico** (o DUnitX desta instalação só existe para Win64 — sem fonte nem DCU Win32). Projeto `Tests\BlessImportTests.dproj`; o exe sai em `Tests\BlessImportTests.exe` e abre o executor gráfico (barra verde/vermelha). ## Arquitetura (enxuta, por decisão do usuário)

- **Sem `TTask`/threads e sem `TAguardeLog`**: processamento síncrono na própria tela, com barra de progresso, contadores e botão Cancelar checado entre as linhas.
- Todos os destinos são Firebird → um único `uDmDestino` (FireDAC) para metadados, consulta e gravação; sem camada de adaptadores/interfaces.
- Units planejadas: `uPerfilModelo` (classes do perfil), `uTransformacoes` (um `case` por tipo de transformação), `uImportador` (linha a linha: obtém valor → transforma → valida → grava), `uLeitorXls`, `uDmDestino`. Telas: `uConexoes`, `uPerfis`, `uPerfilEdicao`, `uImportacao`, `uHistorico`.
- **Transformações (`uTransformacoes`)**: `Transformar(Tipo, Valor, Parâmetro, ObterColuna)` → `TResultadoTransformacao` (`Sucesso`, `Valor`, `Mensagem`); `AplicarTransformacoes` aplica a lista em ordem e para no primeiro erro (mensagem prefixada com o nome da transformação). Catálogo em `cTRANSFORMACOES` (código gravado no perfil, nome, ajuda do parâmetro). Lista gravada como texto, uma por linha `CODIGO|parâmetro` (`TransformacoesParaTexto`/`TextoParaTransformacoes`). Conversões de tipo devolvem `Null` para vazio (quem decide é o valor padrão do campo). Decimal BR exige milhar em grupos de 3 (`601.21` em BR é erro, não 60121). Arredondamento comercial com limpeza de ruído binário (`2,345 → 2,35`). De-para sem `*` e sem correspondência = erro. Telefone (`DDD`, `TELEFONE_SEM_DDD`, via `SepararTelefone`): ignora a pontuação, descarta `0` de discagem e `55` do país (só com 12/13 dígitos, para não confundir com o DDD 55), conta só os dígitos: até 9 dígitos = sem DDD → `DDD` fica em branco (nulo) e `TELEFONE_SEM_DDD` devolve os dígitos como vieram (o DDD só é removido com mais de 9 dígitos); 10/11 dígitos = DDD + número; **DDD `00` = sem DDD** (`00 2102-8800` → DDD em branco, telefone `21028800`); telefone só com zeros (`00 0000-0000`) → em branco. **Exceção pedida pelo usuário à regra de "nada silencioso": essas duas transformações nunca dão erro — telefone inválido (mais de 11 dígitos, nenhum dígito, DDD com um zero como `01`) fica em branco** (só parâmetro errado é erro). Na `CLIENTES F11.xls`: 6.930 de 6.930 telefones sem erro. `PARTE_TEXTO` = `início,quantidade` com início a partir de 1 (semântica do `Copy`; sem quantidade = até o fim). Não usar `Split(..., Count)` do Delphi para "dividir na primeira ocorrência" — ele descarta o resto; usar `DividirNaPrimeira`.
- **Origem do valor** = `TOrigemValor` (`ovNaoImportar`, `ovColuna`, `ovFixo`, `ovPadrao`, `ovConsulta`, `ovGerado`, `ovExpressao`, `ovConsultaSql`), códigos gravados em `PERFIL_CAMPO.ORIGEM` via `cORIGENS`. `ovColuna` = só o valor da coluna (vazio continua vazio); `ovPadrao` = coluna + valor padrão aplicado SÓ nas condições marcadas (`PadraoSeInexistente`/`SeVazio`/`SeInvalido` — inválido = transformação falhou); sem precedência implícita. `ovConsulta` pesquisa no destino usando o valor da coluna (`ConsultaTabela`/`CampoPesquisa`/`CampoRetorno`, `ConsultaSeNaoAchar` = pendência ou nulo — ver "Consulta / referências"). `ovExpressao` usa o mesmo modelo de `Concatenar` (`{Coluna}`). `TCampoPerfil.ValidarConfiguracao` confere o que cada origem exige.
- **Resolução de valores (`uImportador`)** — uma regra só, usada na pré-visualização, na gravação e no exemplo da tela de perfil (`TfrmPerfilEdicao.CalcularExemplo` chama `ResolverCampo`; não duplicar a regra): 1) valor de origem (coluna/fixo/expressão; `ovPadrao` troca pelo padrão só nas condições marcadas — "vazia" também vale para o valor que fica vazio depois das transformações); 2) transformações do campo — **o valor padrão é o valor final e não passa pelas transformações**; se a transformação falhar e "inválido" estiver marcado, usa o padrão; 3) `ConverterParaDestino`: confere tipo, tamanho de texto, casas decimais de `NUMERIC/DECIMAL`, faixa de `SMALLINT/INTEGER`, data com hora em `DATE`, obrigatório sem valor (nulo é aceito se o campo tem `DEFAULT`). Nada é convertido ou cortado em silêncio; só o texto digitado no perfil (fixo/padrão) é convertido para o tipo do campo. Resultado por campo: `TValorResolvido` (`Fonte`, `ValorRecebido`, `Valor`, `TipoErro` = validação/transformação/referência/gravação, `Mensagem`). Linha da planilha chega via `TObterCelula` (nome da coluna → valor + texto; False = coluna inexistente), o que permite testar sem planilha. `ValidarPerfil` aponta erros/avisos do perfil sem ler linhas (campo/coluna/generator/tabela inexistente, fixo/padrão incompatível, obrigatório sem mapeamento, campo calculado).
- **Gravação (`TdmImportacao.Importar`)**: recusa começar se o perfil tiver erro em `ValidarPerfil`. Estratégias (`TEstrategiaGravacao`, gravadas em `PERFIL.ESTRATEGIA`): Inserir; Ignorar existentes; Atualizar (não encontrado = ignorada); Inserir ou atualizar; Só validar. As que procuram o registro usam `PERFIL.CAMPOS_CHAVE` (`"CGC;OUTRO"`, `ListaCamposChave`); chave mapeada, não gerada, com valor (senão erro de validação); chave que acha mais de um registro = erro de gravação na linha. Inserção: gerado → `ProximoValor(generator)` na hora; nulo em campo com `DEFAULT` é omitido. Atualização: não mexe em chaves nem gerados e **vazio não apaga o valor existente**. Ação em erro (`TAcaoErro`): Continuar; Parar (mantém o que foi gravado); Desfazer tudo (uma transação só; erro ou cancelar = rollback de tudo). Commit a cada `cTAMANHO_LOTE` (200) linhas; `EXECUCAO.ULTIMA_LINHA` = última linha com commit (em "Parar", a linha do erro fica de fora). Erros vão para `EXECUCAO_ERRO` (gravados junto com a atualização da execução). Testado com a `CLIENTES F11.xls` (10.102 linhas) num banco de teste dialeto 1 com a `FORNECEDOR` do SIDI: inserir 8.592 em 2,4 s; reimportar com "ignorar existentes" = 8.592 ignoradas, nada duplicado; "desfazer tudo" após 5.637 inserções = nada gravado. **Gravações de teste nunca no banco real do ERP.**
- **Retomada (T09)**: só para execuções `INTERROMPIDA`, `CANCELADA` ou `FALHOU` (`StatusRetomavel`), começando em `ULTIMA_LINHA + 1` — as linhas do lote não confirmado foram desfeitas, então não duplica. A nova execução grava `ID_EXECUCAO_ORIGEM` e `LINHA_INICIO`; o histórico mostra `RETOMADA_POR` e **bloqueia retomar de novo a mesma execução** (retome a mais nova). Avisa se a versão do perfil mudou e, na confirmação, se a planilha é outra. Em "desfazer tudo"/falha na retomada, `ULTIMA_LINHA` volta ao ponto de partida (`vPontoAnterior`). `TfrmPrincipal.AbrirFormEmAba` é pública e devolve o form (o histórico usa para abrir a importação já preparada). Testado: parar na linha 5.639 com 5.637 gravadas e retomar → 4.463 inseridas, 0 chaves duplicadas, 10.100 registros = 10.100 CGCs distintos.
- **Programas de teste de console** que criam o `TfrmPrincipal` sem `Application.Run` terminam com "Runtime error 216" na saída (finalização do DevExpress); o programa real fecha com código 0 — não é bug do programa.
- **Telas durante a importação**: síncrona, com `Application.ProcessMessages` no aviso de progresso (a cada 25 linhas); controles desabilitados; a aba e o programa não fecham durante a importação (`OnCloseQuery` da tela e `TfrmPrincipal.FormCloseQuery`, que pergunta a cada tela aberta e depois confirma "Deseja realmente sair do programa?" — vale para o item Sair e para o X). Antes de gravar, confirmação mostrando o banco de destino (`DescricaoDestino`).
- **Consulta / referências (T10)**: no `ResolverCampo`, o valor da coluna (já transformado) é a chave; `AConsultar` (`TConsultarReferencia`: -1 erro, 0 não achou, 1 achou, 2 mais de um) devolve o campo de retorno, que passa por `ConverterParaDestino` como qualquer valor. Não achou → `ConsultaSeNaoAchar`: pendência = erro de **referência** (linha não é gravada) ou nulo (aviso; obrigatório continua erro). Mais de um registro = erro de referência (nunca escolhe ao acaso). Chave vazia não consulta (fica nulo). Sem `AConsultar` (nil) a origem só mostra a chave (tela sem conexão). `TConsultaReferencias`: uma instância por execução (pré-visualização, importação, tela de perfil — recriada a cada conexão); confere o valor de pesquisa contra o tipo do campo pesquisado (`ConverterParaDestino`, sem conversão silenciosa); lê os metadados de cada tabela uma vez; **cache só dos valores encontrados** (o "não achou" pode passar a existir na mesma importação: a consulta usa a mesma conexão/transação da gravação). `TdmDestino.ConsultarValor` faz `select first 2 RETORNO from TABELA where PESQUISA = :V`. Testado com banco real: 3.906 lançamentos da `A RECEBER F11.xls` resolvendo o cliente por CGC → `FORNECEDOR.CODIGO` em 1,7 s (988 clientes distintos); cliente apagado → 1 erro de referência e o lançamento não foi gravado.
- **Consulta SQL manual (`ovConsultaSql`)**: SELECT escrito no perfil (`TCampoPerfil.ConsultaSql`); `{valor}` = valor da coluna do campo já transformado (coluna obrigatória só se o SQL usa `{valor}`), `{NomeDaColuna}` = valor bruto de outra coluna da planilha. `MontarSqlManual` troca os marcadores por `:P0, :P1…` (sempre parâmetros, nunca texto colado). `TdmDestino.ConferirSomenteLeitura` aceita só `SELECT`/`WITH` sem `;`; `TdmDestino.ConsultarSql` tipa os parâmetros pelo valor e devolve a 1ª coluna da 1ª linha (mesmos códigos -1/0/1/2 da consulta comum; não achou → `ConsultaSeNaoAchar`; mais de uma linha = erro de referência); `TestarSql` prepara o comando (botão Testar e `ValidarPerfil`, que mostra o erro do Firebird). `TConsultaReferencias.ConsultarSql` com cache só dos encontrados; ligado no `TResolvedorValores.ConsultarSql` (pré-visualização, gravação) e no exemplo da tela de perfil. Testado: 3.906 lançamentos com `select CODIGO from FORNECEDOR where CGC = {valor} and RAZAO_SOCIAL is not null` → 3.905 inseridos, 1 erro de referência.
- **Pré-visualização**: `TdmImportacao` mantém a planilha aberta e só relê o arquivo quando ele muda (planilhas grandes); relê o perfil a cada execução; pula linhas totalmente vazias. Medido no perfil real com `CLIENTES F11.xls`: 10.102 linhas simuladas em 0,3 s (abrir a planilha leva ~2 s).
- **Perfil em edição**: `TPerfil.Campos` tem um `TCampoPerfil` por campo da tabela de destino; só os mapeados são gravados (`PERFIL_CAMPO` é apagado e regravado a cada `Gravar`, dentro de transação; `VERSAO` +1). Mudar a tabela descarta os não mapeados e mantém os mapeados (aparecem em laranja como "não existe na tabela"). "Sugerir mapeamento" casa campo e coluna por `NomeNormalizado` (sem acento/espaço/símbolo) e acrescenta conversão texto→inteiro/decimal/data quando a coluna é texto e o campo não. O exemplo de cada campo usa `TColunaPlanilha.ExemploValor` (primeiro valor não vazio, tipado). Grade de campos (`grdCampos`): clique no título ordena (crescente; de novo, decrescente; ▲/▼ no título), via `OnFixedCellClick` ligado no `FormCreate` (`goFixedRowClick`); `FLinhas` guarda a ordem atual e `MontarGrade` reaplica a ordenação; editar um campo não reordena. Combo de colunas (`cbxColuna`) em ordem alfabética. A tela foi reorganizada pelo usuário num `pcPrincipal`; a aba `tsGravacao` (estratégia, ação em erro, campos-chave num `TCheckListBox` com sugestão da chave primária) foi acrescentada na T08. Abas do usuário: `tsBancoDestino` (grade de campos + painel do campo; título = `Tabela 'NOME'`, atualizado em `CarregarCamposDestino`, ou "Tabela de Destino" sem tabela) e `TabSheet2` "Planilha de Origem" (painel de colunas). Transformações = lista ordenada por campo, sem conversão silenciosa e com `TFormatSettings` próprio (formato BR, independente da máquina).

## Bancos de Dados

- **Configurações**: alias `BLESS_IMPORT` (`bin\data\BLESS_IMPORT.FDB`, Firebird 4, **dialeto 3**, conexão em `UTF8`). Parâmetros na seção `[BancoConfig]` do `bin\Config.ini` (Servidor, Porta, Banco); usuário e senha são fixos no código (`cUSUARIO_BANCO`/`cSENHA_BANCO` em `uDmConexao.pas`), não no ini. Sem o ini ou sem conexão, a aplicação avisa e fecha. `fbclient.dll` ao lado do exe tem prioridade sobre o cliente instalado.
- **Destinos**: bancos dos ERPs (aliases locais `SIDI`, `FINANCE`, `INJET`; SIDI em **dialeto 1**, charset WIN1252). No SIDI, clientes ficam em `FORNECEDOR` (179 campos; PK `CGC` = `VARCHAR(14)` só dígitos, enquanto a planilha traz `12.194.177/0001-55`; obrigatórios `CGC`, `SIGLA_UF`, `CODIGO`, `RAZAO_SOCIAL`; `CODIGO` via `GEN_FORNECEDOR`; `CLIENTE = 'T'`). `LANCAMENTO_FINANCEIRO` tem PK composta (`TIPO, TIPO_DOCUMENTO, NUMERO, SERIE, SEQUENCIA, STATUS_SORT`). No dialeto 1 o `DATE` é `TIMESTAMP` (data e hora) e os `NUMERIC` grandes são `DOUBLE PRECISION` — `TdmDestino.MontarTipo` trata isso. **Gravações de teste só numa cópia do banco** (ex.: `bin\data\SIDI_TESTE.FDB`).

## Arquivos de Origem: planilhas `.xls`

Origem = planilhas **Excel `.xls`** (97-2003; `.xlsx` também abre), lidas por `TLeitorXls` (`uLeitorXls.pas`) com `TdxSpreadSheet` criado sem form — não precisa de Excel instalado. Seleção: arquivo → aba → linha do cabeçalho/linha inicial → colunas.

`TLeitorXls`: linhas numeradas como no Excel (1 = primeira), colunas a partir de 0 (A = 0). `Celula(Linha, Coluna)` devolve `TCelula` com `Tipo` (`tcVazia/tcTexto/tcNumero/tcData/tcBooleano/tcErro`), `Valor` tipado (string/Double/TDateTime/Boolean) e `Texto` formatado como o Excel exibe (depende da configuração regional — **usar `Valor`, não `Texto`, para converter números e datas**). No `.xls` a data é um número com formato de data: detectada por `StyleHandle.DataFormat.IsDateTime`. Fórmulas: usa o resultado já gravado/calculado, nunca o texto da fórmula. `Colunas` infere o tipo (Texto, Inteiro, Decimal, Data, Booleano, Vazia) por amostra de 200 linhas; códigos com zero à esquerda vêm como texto. Nomes de coluna repetidos ganham sufixo ` (2)`; sem cabeçalho, `Coluna A`, `Coluna B`…

**Desempenho**: o arquivo inteiro vai para a memória. Medido: `CLIENTES F11.xls` (6,5 MB) 2 s/111 MB; `CLIENTES RECEBIDOS 31-12-2020.xls` (51 MB, 52 mil linhas × 103 colunas) **85 s e 813 MB**. Por isso o exe é `IMAGE_FILE_LARGE_ADDRESS_AWARE` (`.dpr`).

Nas planilhas do cliente o cabeçalho fica na linha 1 e os dados começam na linha 2; nomes de colunas como `Codigo`, `CGC`, `Razao Social`, `Data de Emissao`. Exemplos reais em `docs/` (`Pessoas e Serviços/`, `Financeiro Pagamentos e Recebimentos/`, `Produto/`); alguns arquivos têm 40–51 MB. `Processo revenda de tecidos.docx` descreve o negócio do cliente (revenda de tecidos, SIDI).

## Encoding

`.pas`/`.dpr`/`.dfm` em UTF-8 com BOM e CRLF (conferir com `file`). Neste ambiente o `sed -i` do Git Bash remove os CR — depois de usar `sed`, normalizar de novo (ex.: `node -e` lendo o arquivo, trocando `\r?\n` por `\r\n` e gravando com BOM). `__history/` e `__recovery/` são backups da IDE — ignorar.
